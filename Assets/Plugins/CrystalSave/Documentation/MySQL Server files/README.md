# MySQL transport samples

These examples implement Crystal Save's MySQL HTTP protocol. They store caller-owned save
bytes; they do not deserialize Unity/MemoryPack objects or choose between conflicting saves.
Payload and metadata are separate requests, so a failed request can leave a partial remote save.

## PHP

Use PHP with PDO MySQL and a MySQL-compatible database. Create the database/user, then run
`install.php` once from a trusted administrative environment. It creates CrystalSaveData and
the optional CrystalSaveUsers login-example table. Configure the installer and API through
`CRYSTALSAVE_DB_HOST`, `CRYSTALSAVE_DB_PORT`, `CRYSTALSAVE_DB_NAME`, `CRYSTALSAVE_DB_USER`, and
`CRYSTALSAVE_DB_PASSWORD`. Set `CRYSTALSAVE_API_KEY` and `CRYSTALSAVE_IMAGE_ROOT` for the API.
Defaults in the source are development placeholders, not deployment credentials.

Route `/save`, `/load`, `/metadata`, `/list`, `/delete` and `/uploadImage` to
`mysql_api_sample.php`; the script also accepts `?action=...`. Serve the configured image
directory at `<API base>/img/` as static bytes. Do not execute uploaded files. The local
contract runner uses PHP's development router for API tests; configure static image serving
separately on a deployed web server.

## ASP.NET / Blazor

Use `blazor_backend_sample.cs` as Program.cs in an ASP.NET Web project. The isolated test
project targets .NET 10 and pins MySql.Data 26.7.0. Configure `ConnectionStrings:MySql`,
`ApiKey` and `ImageRoot` through the normal ASP.NET configuration system; environment-variable
equivalents are `ConnectionStrings__MySql`, `ApiKey` and `ImageRoot`. Create the same tables
using the installer/schema above. The API serves images at `/img/` behind its API-key gate.

`blazor_frontend_sample.razor` is an independent HTTP transport demonstration. Its UTF-8
example value is not a Crystal Save payload. Supply exported/game-generated bytes when
integrating it with Crystal Save. It sends the API key on each request and reports errors.

## Contract and validation

Metadata POST uses `{uid, slot, name, ticks, scene, shot, meta}`, with `meta` a dictionary.
GET metadata and list responses use `{slot, name, ticks, scene, shot, meta}`, with `meta` an
array of `{key, value}` pairs. Ticks are .NET DateTime ticks. Empty/missing screenshots and
metadata-only slots are supported. Uploading an image changes its reference, not the timestamp.

From the repository root, run `python3 ci/run_server_tests.py`. It compiles the ASP.NET API
and Razor component, then runs both APIs against a disposable loopback MariaDB instance.
See `docs/testing.md` for external tool provisioning and required CI checks.

These shared-key samples assume trusted callers. A public game service needs authenticated
per-user authorization for every supplied uid, TLS, deployment-specific limits and protected
image access. The optional signup/login example does not authorize the other endpoints.
Neither permissive development CORS nor a key embedded in a game client supplies that boundary.
