**Role**: Principal Engine Architect & Migration Planner  
**Purpose**: Rigorous, code-verified audit of every existing C# subsystem, ScriptableObject database, scene dependency, and third-party coupling against the target Foundational Architecture (`ARCH-01` through `ARCH-08`).

## 1. Executive Summary of Codebase Readiness

A line-by-line inspection of all C# scripts in `Assets/Scripts/`, `Assets/Data/`, and `Assets/Tests/` confirms that the project possesses a **compact, clean, and highly salvagable C# codebase (~45 core/gameplay scripts)**, currently executing inside [`Assets/Scenes/RPGProvingGrounds.unity`](file:///d:/Development/Game%20Development/3D%202D%20World/Assets/Scenes/RPGProvingGrounds.unity).

However, source-code verification uncovered **six critical architectural bottlenecks and hidden runtime bugs** that were not obvious from high-level documentation alone and **must** be accounted for in the migration plan:

1. **Broken Boot Order Between `BlockPlacementService` and `GreedyMeshingService`**:
   - [`GameBootstrapper.RegisterServices()`](file:///d:/Development/Game%20Development/3D%202D%20World/Assets/Scripts/Core/Bootstrap/GameBootstrapper.cs#L95-L128) registers [`BlockPlacementService`](file:///d:/Development/Game%20Development/3D%202D%20World/Assets/Scripts/Systems/Building/BlockPlacementService.cs), which immediately runs `Initialize()` and calls `ServiceLocator.TryGet(out _meshingService)` (line 17).
   - However, [`GreedyMeshingService`](file:///d:/Development/Game%20Development/3D%202D%20World/Assets/Scripts/Systems/Meshing/GreedyMeshingService.cs) is **not registered in `GameBootstrapper`**! Instead, it is instantiated and registered inside [`LevelLayoutRenderer.Awake()`](file:///d:/Development/Game%20Development/3D%202D%20World/Assets/Scripts/Gameplay/World/LevelLayoutRenderer.cs#L57-L58), which runs *after* `GameBootstrapper.Awake()` (or never runs at all in non-voxel scenes like `RPGProvingGrounds.unity`).
2. **Save/Load Orchestration Is Trapped Inside `LevelLayoutRenderer` MonoBehaviour**:
   - [`FileSaveService`](file:///d:/Development/Game%20Development/3D%202D%20World/Assets/Scripts/Systems/Save/FileSaveService.cs) does **not** subscribe to `GameSaveRequestedEvent` or `GameLoadRequestedEvent`.
   - Instead, [`LevelLayoutRenderer.OnSaveRequested()`](file:///d:/Development/Game%20Development/3D%202D%20World/Assets/Scripts/Gameplay/World/LevelLayoutRenderer.cs#L108-L177) subscribes to `GameSaveRequestedEvent`, manually queries `GameObject.FindGameObjectWithTag("Player")`, reads `AttributeComponent`, `SkillProgressionService`, and `InventoryComponent`, packs `LevelSaveData`, and calls `saveService.WriteData(saveData)`.
   - **Consequence**: In `RPGProvingGrounds.unity` (which has no `LevelLayoutRenderer`), pressing F5 / publishing `GameSaveRequestedEvent` does nothing!
3. **Subclass `OnValidate()` Shadowing Bug in `BlockDefinition`**:
   - [`EntityData`](file:///d:/Development/Game%20Development/3D%202D%20World/Assets/Data/Config/EntityData.cs#L17-L24) defines `private void OnValidate()` to schedule auto-ID generation (`AssignNewId()`).
   - [`BlockDefinition : EntityData`](file:///d:/Development/Game%20Development/3D%202D%20World/Assets/Scripts/Domain/World/BlockDefinition.cs#L66-L70) also defines `private void OnValidate()`. In Unity, when a derived `ScriptableObject` defines `private void OnValidate()`, Unity invokes **only** the derived method and silently skips the base class's `private void OnValidate()`. Thus, `BlockDefinition` assets never execute `EntityData.OnValidate()`.
4. **Hard Dependency on `Assets/Cowsins/` Inside `CreatorStudioSetup.cs` and `DefaultCreatorCatalog.asset`**:
   - [`CreatorStudioSetup.PopulateDefaultCatalog()`](file:///d:/Development/Game%20Development/3D%202D%20World/Assets/Scripts/Editor/CreatorStudioSetup.cs#L57-L95) hardcodes 12 asset paths under `Assets/Cowsins/Prefabs/DragAndDropExtras/` (`Turret.prefab`, `ExplosiveBarrel.prefab`, `JumpPad.prefab`, etc.) into `Assets/Data/Creator/DefaultCreatorCatalog.asset`. Archiving `Assets/Cowsins/` before migrating this catalog will break the In-Game Editor catalog with missing prefab references.
5. **Fragile `DisplayName` String Matching Between Inventory Items and Voxel Blocks**:
   - [`HotbarService.ResolveBlock(ItemData item)`](file:///d:/Development/Game%20Development/3D%202D%20World/Assets/Scripts/Systems/HUD/HotbarService.cs#L177-L186) iterates `BlockRegistry.Blocks` and checks `block.DisplayName == item.DisplayName`. Renaming or localizing an item's display name immediately breaks block placement.
6. **Per-Frame Heap Allocations & Missing Faction Checks in `StealthDetectionService`**:
   - [`StealthDetectionService.CheckEnemyLineOfSight()`](file:///d:/Development/Game%20Development/3D%202D%20World/Assets/Scripts/Systems/Skyrim/StealthDetectionService.cs#L120-L125) calls `GameObject.FindGameObjectsWithTag("Enemy")` on every `Update` tick and never consults `FactionService.IsHostile(...)`.

## 4. Verification of Architectural Proposals Against Unity 6 Constraints

We challenged every proposed design in `ARCH-01` through `ARCH-06` against Unity 6 (`6000.3.8f1`) and C# constraints:

| Proposed Architectural Feature | Unity / C# Constraint | Verification & Required Adjustment |
|---|---|---|
| **`ResourceId` on `ScriptableObject` Inspectors** | Unity's built-in serializer cannot serialize `readonly struct` fields unless marked `[Serializable]` with `[SerializeField] private string _raw;` backing field. | **Adjustment**: Implement `ResourceId` with `[Serializable]` and `[SerializeField] private string _value;`, plus a custom `PropertyDrawer` (or Odin `[InlineProperty]`) so Unity Inspector and `JsonUtility` / `Newtonsoft.Json` serialize it seamlessly. |
| **Async Module Initialization (`InitializeAsync`) in `GameBootstrapper.Awake()`** | In Unity, `Awake()` is synchronous; if `InitializeAsync()` yields across frames before completion, scene `MonoBehaviour.Start()` methods in `RPGProvingGrounds.unity` will execute *before* services finish initializing! | **Adjustment**: For built-in modules and synchronous boot in `RPGProvingGrounds.unity`, `ModuleHost` **must** complete Phase 1 (`RegisterServices`) and Phase 2 (synchronous registry hydration) **synchronously inside `Awake()`** before any scene `Start()` runs, using async continuation only when loading external disk/AssetBundle mods from a loading screen or profile switch. |
| **Burst Compatibility with `ResourceId`** | `[BurstCompile]` jobs (`GreedyMeshingJob`) forbid managed `string` fields inside `NativeArray<T>` or `NativeHashMap<K,V>`. | **Adjustment**: `RoomGridData` retains `ushort[] Grid` at runtime. `VoxelPaletteMap` maps `ResourceId <-> ushort` on the main thread when loading/saving chunks. |
| **Subclass `OnValidate` Shadowing** | `EntityData.OnValidate()` was `private`, shadowed by `BlockDefinition.OnValidate()`. | **Adjustment**: Change `EntityData.OnValidate()` to `protected virtual void OnValidate()` and call `base.OnValidate()` in `BlockDefinition`. |
